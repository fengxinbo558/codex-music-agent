# 怒声摇滚与极限嘶吼实施计划

## 目标

在现有生成设置、Codex 规划、本地兜底规划器和 ACE-Step Provider 中加入统一的演唱状态，并为过长文案提供时长提示。

## 实施步骤

### 1. 建立演唱状态数据模型

- 在 `src/types.ts` 增加 `VocalDelivery`。
- 在 `GenerationPreferences` 增加 `vocalDelivery`。
- 新建独立的演唱状态定义模块，集中维护标签、说明、规划方向、正向提示和负向提示。
- 默认值使用 `natural`，保证旧偏好数据兼容。

### 2. 增加设置界面与摘要

- 在 `GenerationSettings` 中加入“自然演唱 / 怒声摇滚 / 极限嘶吼”三档卡片。
- 纯音乐时禁用该设置。
- 在折叠摘要中显示演唱状态。
- 增加歌词/文案容量提示，不阻断生成。

### 3. 让 Agent 规划真正响应演唱状态

- 在 `PlanMusicRequest` 中传递演唱状态。
- Electron 端校验该字段，并把对应歌词写作方向加入 Codex 规划提示。
- AI 自动写词使用状态化写法；使用当前歌词仍由 App 保持原字。

### 4. 改进浏览器预览的本地兜底规划

- 根据演唱状态生成不同的曲风、配器、情绪和原创歌词。
- 从用户文案中抽取一个短主题，避免所有请求都返回同一组雨夜歌词。
- 怒声摇滚保持歌词清晰；极限嘶吼使用短句与重复钩子。

### 5. 接入 ACE-Step 请求

- 把演唱状态正向提示加入 `prompt`。
- 把抗刺耳、抗削波和抗失控噪声约束加入 `lm_negative_prompt`。
- 纯音乐时不注入人声方向。

### 6. 测试与验证

- 为偏好摘要、旧数据兼容和内容容量提示补充单元测试。
- 为本地兜底歌词和配器差异补充测试。
- 为 ACE-Step 三档请求与纯音乐行为补充测试。
- 运行全部 Studio 测试、类型检查和生产构建。
- 在本地页面验证三档设置、禁用状态、摘要与长文案提示。

### 7. 发布

- 提交实现代码。
- 更新 GitHub 发布快照并推送到私有仓库 `fengxinbo558/codex-music-agent` 的 `main` 分支。
