# 小白创作全流程细化：实施计划

设计依据：`docs/superpowers/specs/2026-08-28-novice-creation-details-design.md`

## 1. 扩展生成领域模型

- 在 `src/types.ts` 增加生成偏好、版本音频快照和结果数组类型。
- 将 `MusicProvider.generate` 改为接收偏好并返回一个或多个结果。
- 先补充参数映射、多结果和离线限制测试，再修改 ACE-Step 与原型 Provider。

## 2. 建立真实参数映射

- 时长映射到 `audio_duration`。
- 版本数量映射到 `batch_size`。
- 创意程度映射到 LM temperature / top-p。
- 演唱方式写入音乐提示；纯音乐时不发送歌词。
- 下载任务返回的全部音频并保留 seed、时长、Provider 信息。

## 3. 加入渐进式创作设置

- 新增 `GenerationSettings` 受控组件。
- 在 Agent 输入区增加配方摘要、可展开设置和预计耗时。
- 保持默认折叠、完整标签、键盘访问、`aria-expanded` 和状态说明。
- 增加对应窄屏样式，保证主按钮仍在时间线之前。

## 4. 完成版本音频生命周期

- App 将每个生成结果转换为独立 `ProjectVersion`。
- 选择版本时切换音频、时长、歌词、BPM、调性和轨道快照。
- 只在版本离开内存或应用卸载时释放 Blob URL。
- 新建作品清空作品级状态，但保留用户生成偏好。

## 5. 加入生成后动作和恢复

- 新增 `GenerationResultActions`。
- 接通“再来一版、只改副歌、新建歌曲、导出当前版”。
- 保存上一次请求，让失败状态可一键重试。
- 任务记录显示时长、演唱方式和版本数量。

## 6. 验证

- 运行全部单元测试与 TypeScript 生产构建。
- 检查 Electron 主进程语法、ACE-Step 健康状态和跨域。
- 实际提交一次双版本 ACE-Step 任务，分别下载并检查两个 WAV。
- 验证 416px 规则中设置、按钮和结果动作位于时间线之前。
- 更新 README，明确连续新歌、同歌多版本和真实参数能力。

验证结果（2026-08-28）：

- 8 项单元测试通过，TypeScript 与 Vite 生产构建通过。
- Electron 主进程与 preload 语法检查通过。
- ACE-Step 本地服务模型已就绪；双版本任务一次返回两份独立 WAV。
- 两份 WAV 均为 30 秒、48 kHz、双声道 PCM，实测总生成时间约 54.5 秒。
- 应用内浏览器因本机安全策略未能自动接管；未绕过安全策略，移动端以响应式规则与生产构建完成静态核对。
