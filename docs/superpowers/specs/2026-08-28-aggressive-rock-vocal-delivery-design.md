# 怒声摇滚与极限嘶吼演唱状态设计

## 目标

在不增加专业操作负担的前提下，为 Codex Music Agent Studio 增加两种有明确差异的演唱状态：

- **怒声摇滚**：沙哑、爆发、有受控破音，优先保证中文歌词可听清。
- **极限嘶吼**：使用 scream / growl 式重型唱法，允许部分牺牲歌词清晰度来换取冲击力。

这两个状态必须同时影响歌词规划、ACE-Step 生成提示、编曲倾向和负面约束，不能只成为一个没有实际作用的界面标签。

## 用户体验

在“这次怎么做”中新增“演唱状态”，提供三张单选卡：

1. 自然演唱（默认）
2. 怒声摇滚
3. 极限嘶吼

“演唱方式”继续负责女声、男声和纯音乐；“演唱状态”负责自然、怒唱和嘶吼，两者职责分开。选择纯音乐时，演唱状态不可操作，生成请求也不包含人声方向。

每个状态展示一句小白能理解的说明。摘要条会同时显示演唱方式和状态，例如“男声 · 怒声摇滚”。

## 歌词与文案规则

### AI 自动写词

用户输入的是故事、文案或观点时，Agent 将其视为创作素材，而不是逐字歌词：

- 怒声摇滚：改写为短句、重音明确、带反抗与爆发感的主歌和副歌。
- 极限嘶吼：使用更短、更适合吼腔的句子，并保留一个可重复的核心钩子。

### 使用当前歌词

用户在歌词编辑器中写入的内容保持原字，不由 Agent 改写。演唱状态只改变唱法、配器与声音表现。

### 内容容量

30 秒不承诺唱完长文案。系统根据当前歌词或输入文字的长度显示清晰提示：内容明显超出当前时长时，建议切换到 60 或 90 秒。提示不阻止生成，但不能再让用户误以为长文案会被完整演唱。

## 数据与生成链路

新增独立字段：

```ts
type VocalDelivery = "natural" | "angryRock" | "extremeScream";
```

该字段进入 `GenerationPreferences`，默认值为 `natural`，并沿用现有偏好持久化机制。

生成链路如下：

1. 界面选择演唱状态。
2. App 在请求 Codex 规划时加入对应的歌词写作方向。
3. Codex 或本地兜底规划器生成与状态匹配的原创歌词草稿。
4. ACE-Step Provider 将演唱技巧、摇滚配器和动态方向写入正向提示。
5. Provider 同时加入针对刺耳尖叫、数字削波、齿音和不可控噪声的负面提示。
6. 生成后的音频继续经过现有声音质感处理并保存为新版本。

## 三档声音契约

### 自然演唱

保持当前行为，不额外强化摇滚或极端发声。

### 怒声摇滚

- 受控沙哑和 vocal fry
- 胸声爆发与摇滚 belt
- 副歌力度明显打开
- 失真吉他、强鼓和贝斯推进
- 中文咬字尽量清楚
- 避免尖锐高频、刺耳齿音、削波和廉价数字失真

### 极限嘶吼

- scream / growl / harsh vocal
- 短句、重拍和重复钩子
- 重型失真吉他、强烈鼓组与停顿冲击
- 允许清唱与嘶吼交替，但不强制
- 避免薄而尖的尖叫、失控噪声、数字爆音和持续刺耳高频

## 本地兜底行为

浏览器预览没有 Codex 桌面桥接时，兜底规划器也必须真正响应演唱状态，不能继续无条件返回同一组雨夜示例歌词。兜底歌词会根据用户文字抽取主题，并分别使用自然、怒声摇滚或极限嘶吼的句式模板。

## 异常与反馈

- ACE-Step 未连接时保留现有试听兜底，同时在结果中说明不代表真实嘶吼质量。
- 极限嘶吼的歌词清晰度天然低于怒声摇滚，界面用简短说明提前告知。
- 时长不足只提示，不自动篡改用户选择。
- 不模仿具体歌手，也不使用“某某歌手的怒声”作为提示。

## 测试与验收

- 默认偏好仍为自然演唱，旧数据可正常加载。
- 三种状态的摘要、禁用逻辑和持久化正确。
- 怒声摇滚请求包含清晰怒唱、摇滚配器与抗刺耳约束。
- 极限嘶吼请求包含 scream / growl 与抗削波、抗尖叫约束。
- 纯音乐请求不包含任何人声或嘶吼方向。
- AI 自动写词会受状态影响；使用当前歌词时保持用户文字不变。
- 长内容在 30 秒设置下出现时长建议。
- 原有测试、类型检查和生产构建全部通过。
