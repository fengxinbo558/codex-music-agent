# 音乐创作台：人机确认、真实分轨与逐句演唱设计

日期：2026-08-29  
状态：用户已确认设计，等待规格复核  
适用范围：`music-studio` 本地产品 Demo

## 1. 背景与目标

当前版本已经能够调用 ACE-Step 生成并保存真实 WAV，但仍有四个结构性问题：

1. 用户提交创意后，规划、歌词、编曲和音乐生成连续自动执行；界面展示了多个 Agent，却没有真正的人类确认门。
2. 右侧流程、输入区和主工作区各自滚动，窄窗口生成后会把动作按钮顶出可见范围。
3. 时间线用混合 WAV 构造多条结构示意轨，不是真实人声、鼓、贝斯和乐器分轨，不能承担编辑承诺。
4. 用户只能描述整首歌曲，不能在某一句、某个词或某个时间范围上设计唱法、精确升降音高或局部重唱。

本设计把产品从“一句话直接生成”升级为“小白可以指导一支音乐制作团队”：AI 负责推荐和执行，用户在关键阶段确认，所有可点击功能都必须连接真实输入、处理和结果。

成功标准：

- 音乐模型只能在用户确认创作方向和歌词结构后启动。
- 默认只设置两个必要确认门，并提供“先做核心小样”的风险控制，不把流程做成频繁审批。
- 用户可以选中歌词中的整句、词语或手动时间范围，添加演唱技巧，并在生成后局部重唱。
- 用户可以对真实分离的人声片段执行确定性的半音升降，修改结果保存为新版本。
- 时间线只展示真实音频资产；分轨未完成或失败时不显示假音轨和假混音控件。
- 生成、分轨、编辑、删除和恢复状态在同一主界面内可见，关键动作始终可达。
- 用户可见品牌不再出现 Codex 名称或 `C/` 标志。

## 2. 产品原则

### 2.1 人确认的是产出，不是进度动画

每个确认阶段必须产生可查看、可修改、可版本化的资产。点击“确认并继续”后，该资产快照成为下一个阶段的唯一权威输入。

阶段状态固定为：

- `DRAFT`：Agent 正在准备候选结果。
- `AWAITING_CONFIRMATION`：等待用户选择或修改。
- `APPROVED`：用户已确认，允许下游阶段读取。
- `REVISING`：用户反馈已写入当前分支，重新生成本阶段候选。
- `FAILED`：真实处理失败，保留输入和上一个已批准资产。

进度列表不能代替这些状态，也不能自动把 `AWAITING_CONFIRMATION` 变成 `APPROVED`。

### 2.2 默认简单，深度控制按上下文出现

首页不陈列全部演唱术语。AI 先为当前歌词推荐两到三个最有意义的唱法；用户点击一句歌词或“更多唱法”后，才展开完整控制。

### 2.3 生成式修改与确定性编辑分开

- 怒音、哭腔、气声、真假声转换等改变演唱表演的要求走 ACE-Step 局部重绘，结果具有随机性，一次返回两个候选。
- 升高或降低若干半音走真实人声分轨和音频处理，结果是确定性的。
- 产品文案必须明确区分“重新演唱”和“精确音高”，不能把提示词理解描述为精确编辑。

### 2.4 不伪装能力

- 混合 WAV 只显示一条完整波形。
- 只有真实 Stem 文件保存成功后，才显示对应音轨、静音、独奏、音量和声像控件。
- 分轨失败不影响原歌曲播放，但不允许用模拟波形填充音轨。
- 尚未接通的能力不显示为主要可点击按钮。

## 3. 创作流程与确认门

采用“双确认门 + 核心小样确认”，不采用每个 Agent 都弹一次确认，也不采用一次提交后全部自动完成。

### 3.1 阶段一：填写创意

入口只要求用户说明想做什么。用户可附加：

- 自己的歌词、对话或文案。
- 参考音频与参考方式。
- 必须出现或必须避免的词句。
- 希望强调的情绪或演唱方式。

提交动作只启动音乐总监规划，不启动音乐生成模型。

### 3.2 确认门一：创作方向

音乐总监返回三张候选方向卡：

1. **推荐方案**：最符合创意且模型成功率较高。
2. **稳妥方案**：结构清楚、演唱难度较低。
3. **大胆方案**：情绪、节奏或配器更鲜明。

每张卡显示：曲风、情绪、BPM、调性、人声类型、声音质感、主要配器、结构、预计时长和推荐理由。用户可以：

- 采用并继续。
- 修改卡片字段后采用。
- 换一组推荐。
- 返回修改原始创意。

只有一张方向卡进入 `APPROVED` 后，词作和编曲阶段才开始。

### 3.3 确认门二：歌词、结构与演唱设计

这一阶段展示一个可编辑的歌词资产，而不是只显示行数。内容包括：

- 主歌、预副歌、副歌、桥段和尾奏标签。
- 原始用户文字和 AI 补写内容的来源标识。
- 过长、难唱、可能咬字模糊或不适合当前节拍的行级提示。
- 每句歌词旁的演唱推荐和推荐原因。
- 结构时长估计以及歌词是否能在目标时长内唱完。

用户可修改歌词、重新推荐某一段、恢复上一版，也可以确认歌词和演唱设计。确认后保存不可变快照；后续修改创建新分支，不覆盖已生成版本所用歌词。

### 3.4 核心小样确认

默认先生成 20 至 30 秒小样，优先覆盖副歌和最强情绪点。小样完成后提供：

- 满意，生成整首。
- 人声更清楚。
- 情绪更强或更克制。
- 修改选中歌词。
- 换演唱方式。
- 返回修改创作方向。

用户可以主动选择“直接生成整首”，但该选择必须明确显示预计耗时和返工风险；默认推荐小样路线。

### 3.5 整首生成与交付

用户确认小样后才提交整首 ACE-Step 任务。混合 WAV 返回并保存成功后立即允许播放；真实分轨在后台运行，不阻塞整首试听。

交付完成的最低条件：

- 混合音频可播放。
- 音频 Blob 已存入本机素材库。
- 歌词、方向、模型参数和版本关系已保存。
- 播放歌词时间轴已建立，无法自动逐字对齐时明确降级为逐句。

## 4. Agent 与工具边界

Agent 不按人物数量堆界面，只在其拥有真实输入和输出时存在。

| 角色 | 输入 | 输出 | 是否需要确认 |
| --- | --- | --- | --- |
| 音乐总监 | 用户创意、参考素材 | 三套方向候选 | 是 |
| 词作与结构顾问 | 已批准方向、用户文字 | 可演唱歌词、段落结构、风险提示 | 是 |
| 演唱指导 | 已批准歌词、方向 | 逐句 `VocalCue` 推荐 | 与歌词一起确认 |
| 小样制作 | 已批准方案 | 20–30 秒真实小样 | 是 |
| ACE-Step Turbo | 已批准方案 | 小样、整首或局部重绘 WAV | 工具，不冒充 Agent |
| 分轨服务 | 已保存混合 WAV | 真实 Stem 资产 | 后台工具 |
| 音高编辑器 | 人声 Stem、时间范围、半音数 | 新人声片段 | 用户直接操作 |
| 母带与质检 | 新混合、元数据 | 可交付检查结果 | 失败时阻断交付状态 |

右侧工作流只展示当前阶段、已批准产出摘要和下一步动作。完整历史放在可展开的“制作记录”中。

## 5. 逐句演唱设计

### 5.1 选择范围

用户可以通过三种方式确定编辑目标：

- 点击整句歌词。
- 在歌词中框选一个或多个字词。
- 在真实波形上拖动开始和结束时间。

歌词选择和时间选择双向同步。自动对齐不准确时，以用户最后调整的波形范围为准。

### 5.2 `VocalCue` 数据

每项演唱设计单独保存，不把所有信息拼进一段不可解析提示词：

```ts
type VocalCue = {
  id: string;
  lyricLineId: string;
  characterStart: number;
  characterEnd: number;
  startSeconds?: number;
  endSeconds?: number;
  technique: VocalTechnique;
  intensity: 1 | 2 | 3;
  pitchSemitones?: number;
  timingOffsetMs?: number;
  durationDeltaMs?: number;
  clarity?: "natural" | "clear" | "emphasized";
  source: "recommended" | "user";
  reason?: string;
};
```

### 5.3 技巧分类

默认只显示 AI 推荐；“更多唱法”展开完整分类：

| 分类 | 选项 |
| --- | --- |
| 情绪唱法 | 怒音、哭腔、呐喊、克制、温柔、冷淡、爆发 |
| 声线质感 | 气声、沙哑、颗粒感、清亮、厚实、贴耳、空灵 |
| 音区走向 | 高音区、低音区、尾音上扬、尾音下坠、真假声转换、八度跳跃 |
| 装饰技巧 | 颤音、转音、滑音、倚音、拖腔、尾音延长 |
| 节奏表达 | 停顿、抢拍、慢半拍、断唱、连唱、念白、说唱 |
| 清晰程度 | 咬字清楚、强调选中字词、增加换气、减少拖音 |

不兼容的组合在选择时提示，例如“强烈怒音”和“贴耳气声”不能同时作为同一个短片段的主要技巧。AI 推荐包含理由，用户采用后可以继续调整强度。

## 6. 真实分轨与精确音高

### 6.1 本地处理架构

采用多工具本地链路，不要求单个生成模型包办所有任务：

1. **ACE-Step Turbo**：小样、整首和局部重绘。
2. **Demucs `htdemucs`**：默认生成可重构的 `vocals`、`drums`、`bass`、`other` 四 Stem；ACE-Step 2B Base `extract` 作为分轨失败时的备用，并承担吉他、键盘等扩展乐器提取。
3. **FunASR `paraformer-zh` 时间戳模型**：对人声 Stem 生成中文词级时间戳，再用已知歌词做编辑距离对齐，输出逐句、逐词范围和置信度。
4. **TorchCrepe**：分析选区的人声基频曲线，并忽略无声和非周期片段。
5. **`torchaudio.functional.pitch_shift`**：保持时长，对选中人声执行确定性半音移动。
6. **SoundFile + NumPy 混合器**：完成样本级等长、边界交叉淡化和响度匹配，再与未修改 Stem 合成。

当前机器为 32GB Apple Silicon，已安装 ACE-Step Turbo、1.7B LM、TorchAudio、SoundFile 和 SciPy；Demucs、`htdemucs` 权重、FunASR、TorchCrepe 与 ACE-Step 2B Base 需要在实施阶段安装并进行真实速度、内存和质量基准。XL Base 不作为第一版依赖。

这些能力封装在独立 `LocalAudioService` 中，通过受控本机接口接收音频资产 ID 和编辑参数。前端不直接调用 Python 包，也不读取任意文件路径。服务接口固定为：

- `POST /local-audio/stems`：返回四个真实 Stem 资产。
- `POST /local-audio/align-lyrics`：返回歌词字符范围、时间范围和置信度。
- `POST /local-audio/analyze-pitch`：返回选区基频摘要和可编辑性判断。
- `POST /local-audio/shift-pitch`：返回等长的新人物声片段和验证结果。
- `POST /local-audio/mix`：返回重新合成的混合 WAV。

接口只返回任务 ID、进度和已登记资产，不向浏览器暴露本机绝对路径。

### 6.2 后台分轨行为

整首混合 WAV 保存后立刻可播放，同时启动后台分轨。状态依次显示：

- 正在准备真实音轨。
- 正在人声分离。
- 正在生成其余 Stem。
- 正在校验长度与可重构性。
- 真实音轨可编辑。

每条 Stem 必须具有独立 Blob、真实时长、波形和来源元数据。长度异常、空音频或重构质量未过门时，该 Stem 不进入可编辑状态。

### 6.3 精确音高行为

用户对已分轨的人声范围设置半音变化：

- 快捷值：`-3`、`-2`、`-1`、`+1`、`+2`、`+3`。
- 高级值：`-12` 至 `+12`。
- 保持片段时长不变。
- 修改前后各增加短交叉淡化，避免爆音和断裂。
- 修改后重新检测基频，验证中位音高变化接近目标半音数。
- 绝对值超过 3 时提示可能出现音色失真，并推荐“重新演唱”。

每次应用创建一个新版本，其中保存旧人声 Stem、新人声 Stem、处理参数、混合结果和父版本 ID。撤销只切回父版本，不逆向破坏音频。

### 6.4 表演技巧的局部重唱

怒音、哭腔、气声等选择不能通过简单滤镜伪造。局部重唱流程为：

1. 根据歌词对齐和用户微调确定重绘范围。
2. 自动加入前后上下文缓冲，避免接缝。
3. 把选中歌词、唱法、强度和原歌曲作为 ACE-Step `repaint` 输入。
4. 返回两个真实候选。
5. 用户 A/B 试听并采用一个候选。
6. 保存新混合，重新对受影响范围执行歌词对齐和分轨。

局部重唱是生成式操作，界面不承诺与旧旋律逐音一致；需要严格保留旋律时，优先使用确定性音高编辑。

## 7. 时间线与播放界面

### 7.1 分轨前

只展示一条“完整歌曲”真实波形以及：

- 点击定位和拖动播放头。
- 歌曲段落标记。
- 当前歌词高亮。
- 选择时间范围。
- “分轨准备中”的真实状态。

不显示禁用的假 M/S 按钮，也不显示模拟的人声、鼓或氛围层。

### 7.2 分轨后

时间线替换为真实 Stem：

- 每轨真实波形。
- 静音、独奏、音量和声像。
- 选择人声片段后出现“唱法”和“音高”动作。
- 歌词点击、播放头和选区同步。
- 所有编辑都生成新版本。

第一版不做自由拖拽编曲、任意插件链、MIDI 钢琴卷帘或完整 DAW；时间线只承担听、看、选、局部改和真实混音。

## 8. 页面布局与滚动

桌面采用稳定三栏，但只有主内容和右侧内部记录可以按需滚动：

```text
┌────导航────┬────────当前创作资产────────┬────当前步骤────┐
│ 音乐符号   │ 方向 / 歌词 / 小样 / 时间线│ 推荐与确认     │
│ 项目       │                            │                │
│ 素材库     │                            │                │
│ 模型       │                            │ [固定主动作]   │
└────────────┴────────────────────────────┴────────────────┘
```

- 右侧只展示当前步骤，底部主动作固定在可见区域。
- 已完成阶段折叠为摘要，不把八张大卡常驻页面。
- 移除 `agent-scroll + agent-composer + viewport` 三层滚动竞争。
- 一个区域只能有一个纵向滚动拥有者。
- 窄窗口切换为“创作流程 / 编辑工作台”两个顶层页签，不把右栏和编辑器纵向无限堆叠。
- 在 760px、1024px、1280px 和桌面全屏下均需验证主按钮、删除和返回动作可达。

## 9. 品牌、文案与删除

### 9.1 品牌

- 用户可见产品名统一为“音乐创作台”。
- `C/` 替换为原创音符与波形组合标志。
- 移除标题、侧栏、对话框、模型中心和状态提示中的 Codex 文案。
- 内部规划来源只显示“音乐制作助理”或“本机音乐规划器”。内部存储键可以在兼容期继续保留旧名称，不暴露给用户。

### 9.2 删除

版本卡片、播放详情和素材库均提供删除入口。删除前确认将移除的内容：

- 当前版本记录。
- 该版本的混合 WAV、源 WAV、Stem、歌词时间轴和编辑产物。
- 仅被该版本引用的本地 Blob。

删除当前播放版本时先停止播放并切换到最近可用版本。删除失败时不先从界面移除记录。第一版采用二次确认的永久删除；不声称存在尚未实现的云端回收站。

## 10. 状态、资产与版本关系

核心对象：

- `CreationSession`：当前人机确认流程及阶段状态。
- `DirectionProposal`：三套方向候选与用户修改。
- `LyricDraft`：歌词、结构、来源和风险提示。
- `VocalCue`：逐句或逐词演唱设计。
- `SampleVersion`：小样音频及确认反馈。
- `ProjectVersion`：整首版本和父版本关系。
- `AudioAsset`：混合、源音频、Stem 或局部处理结果。
- `LyricAlignment`：歌词字符范围与音频时间范围、置信度。
- `AudioEditOperation`：重绘、音高、时长或混音处理记录。

数据流：

```text
用户创意
  ↓
三套方向候选 ──用户确认──→ 已批准方向
  ↓
歌词结构 + VocalCue 推荐 ──用户确认──→ 已批准演唱方案
  ↓
真实核心小样 ──用户确认──→ 整首 ACE-Step 任务
  ↓
混合 WAV 立即播放、保存版本
  ├──后台真实分轨──→ Stem + 歌词对齐 + 基频
  ├──演唱技巧修改──→ ACE-Step repaint 两候选──→ 新版本
  └──精确音高修改──→ 人声 DSP + 重新混合──→ 新版本
```

页面刷新后从本机数据库恢复最近一个会话、已批准资产、版本树和真实音频；不能只恢复 UI 标签而丢失 Blob 引用。

## 11. 错误处理与恢复

- 方向或歌词推荐失败：保留用户输入，允许使用内置规则生成候选，不启动音乐模型。
- 小样生成失败：停留在小样阶段，保留已批准方向、歌词和唱法。
- 整首生成失败：小样仍可播放，可按相同参数重试。
- 分轨模型未安装：混合 WAV 正常交付，显示明确安装状态，不显示假 Stem。
- 分轨失败：保留原音频，允许重试，不开放精确音高。
- 逐词对齐置信度低：降级到逐句，并要求用户微调波形范围。
- 局部重绘失败：原版本不变，候选不进入版本树。
- 音高修改失真或验证偏差过大：不自动采用，提供原片段和处理片段 A/B 对比。
- 保存失败：不显示“已交付”；释放本轮临时对象并保留任务错误记录。
- 删除失败：版本和音频继续显示，提示具体失败资产。

## 12. 验收与测试

### 12.1 状态与确认

- 提交创意后不会调用 ACE-Step，直到方向和歌词阶段均为 `APPROVED`。
- “修改”只重新运行当前阶段，不会偷偷启动下游任务。
- 小样默认先于整首；用户选择直接整首时记录明确授权。
- 刷新页面后仍能恢复等待确认的阶段和已批准快照。

### 12.2 真实音频

- 只有混合 WAV 时只出现一条波形。
- 每条显示的 Stem 都对应可读取的独立 Blob，时长与混合音频在允许误差内。
- 静音、独奏、音量和声像确实改变播放结果。
- 对 `+2` 半音处理后的测试片段执行基频验证，结果接近目标比率 `2^(2/12)`。
- 音高处理保持时长，接缝处无明显爆音。
- 局部重绘请求携带真实源音频、歌词、时间范围和唱法参数。

### 12.3 产品与布局

- 用户可见区域不存在 Codex 或 `C/`。
- 版本、详情和素材库均可执行真实删除。
- 窄窗口生成前后均能滚动到所有内容，固定确认按钮不遮挡输入或播放器。
- 键盘能够完成方向选择、歌词编辑、确认、播放、选区和删除确认。
- 降级和失败状态不显示伪完成、伪分轨或伪保存。

### 12.4 实机验收

- 在当前 32GB Apple Silicon 上完成一次 30 秒中文歌曲：生成、保存、分轨、逐句对齐和播放。
- 对一句歌词执行 `+2` 半音，保存并 A/B 试听。
- 对另一句执行“明显怒音”局部重唱，从两个候选中选择并生成新版本。
- 验证删除新版本不会删除仍被父版本引用的资产。
- 运行类型检查、生产构建、单元测试、浏览器交互测试和真实 ACE-Step API 冒烟测试。

## 13. 实施分段

本规格是一套连续产品链，但实施必须按可独立验收的阶段推进：

1. 修复布局、品牌和真实删除；移除假音轨。
2. 建立人机确认状态机、三套方向卡和歌词结构确认。
3. 接入真实核心小样确认和整首任务。
4. 接入真实分轨、Stem 存储和真实混音播放。
5. 接入歌词对齐、逐句 `VocalCue` 设计和局部重唱。
6. 接入确定性半音编辑、验证、重新混合和版本树。
7. 完成异常恢复、响应式和全链路实机验收。

任何阶段都不能为了视觉完整提前放出下一阶段的假控件。

## 14. 非目标

- 登录、支付、云端同步和公开发布。
- 声音克隆、未经授权模仿真人或歌手身份。
- 完整 DAW 的自由编曲、插件市场、MIDI 编辑和母带工程。
- 保证生成式怒音或哭腔每次完全相同。
- 把超过 ±3 半音的处理宣传为无损音色转换。
- 在本地真实链路可用前依赖按次收费的云端音乐 API。

## 15. 对既有规格的覆盖关系

本规格在冲突处覆盖之前的“一次点击直接生成”和“模拟多轨时间线”设计：

- 默认主路径从一次点击改为两个确认门和一次小样确认。
- 原 `createGeneratedTracks` 结构示意不能继续作为可编辑音轨来源。
- 原右侧八步流程改为当前阶段卡和可展开制作记录。
- 原“分轨未来开放”改为本轮真实本地能力，但只有通过真实验收后才在 UI 开放。
- 既有真实 ACE-Step 生成、本地音频保存、参考音频、清晰柔和母带和歌词播放能力继续复用。
