# 歌词忠实度、真实同步与 A/B 试听闭环设计

## 1. 背景与问题证据

当前 Demo 把已批准歌词按句长平均分配到整首音频，没有分析实际人声。对现有 60 秒完整版本的人声 Stem 做本地转写后发现，主要演唱集中在约 0–29 秒，但界面把八句歌词排到约 4–56 秒，因此歌词必然越来越慢。

当前生成链路还有三处错误：

1. ACE-Step 返回音频后，没有转写实际演唱，也没有比较实际演唱与批准歌词。
2. 质量门只检查“存在歌词数组和估算时间轴”，却显示“歌词可跟唱、已经核验”。
3. 完整歌曲被强制生成一个版本，而 A/B 对比页没有独立播放，只能直接把版本设为当前。

这次修复的目标不是让字幕看起来大致移动，而是建立“内容逻辑、歌词输入、实际演唱、真实时间轴、用户采用”闭环。

## 2. 产品成功标准

### 2.1 歌词先讲得通

- 长素材不能直接压缩成几句押韵口号。先提取人物、场景、关键事实、因果、转折、立场和结论，形成可见的“内容骨架”。
- 每个歌词段落必须有明确任务：主歌交代事实，预副歌制造转折，副歌表达核心判断，尾声完成收束。
- 生成歌词时保存“素材事实 → 段落目的 → 歌词句”的映射；用户可以看到哪些事实被保留、删减或改写。
- 不允许为了押韵引入原素材没有的结论，也不允许把专有名词、人物、球队或关键数字改成空泛意象。
- 当素材无法在目标时长内讲清时，产品必须推荐延长、拆成上下集或选择重点，不能静默丢掉大部分内容。

### 2.2 歌词忠实

- “使用当前歌词”时，不允许规划器改写已批准文字。
- 提交模型前只允许添加结构标签、换行和演唱说明；正文字符及顺序保持不变。
- 对中文歌词按 6–10 个字的可唱短句自动拆分，保留原字序，并用 `[Intro]`、`[Verse]`、`[Pre-Chorus]`、`[Chorus]`、`[Outro]` 组织结构。
- 生成后对真实人声 Stem 转写，并与批准歌词做顺序约束对齐。
- 低于忠实度阈值的版本标记为“歌词未通过”，不得显示“已完成”或“可交付”。

### 2.3 中文咬字可懂

- 清晰模式不仅写入 Prompt，还必须在生成后通过真实人声转写置信度和人工可试听检查。
- 专有名词、数字、结论句和副歌钩子作为重点词单独统计，不能被总体平均分掩盖。
- 低置信度、吞字、含混同音和过度拖音的句子标为“咬字未通过”，展示实际听到的近似转写和对应原词。
- 咬字不通过时优先重生成该候选；不能通过后期 EQ 或移动字幕伪装成清楚。

### 2.4 真实同步

- 卡拉 OK 时间轴只接受两种来源：`aligned` 或明确标注的 `estimated`。
- 新生成的人声歌曲必须完成真实对齐后才能通过交付门；估算时间轴只能作为处理中的临时状态。
- 对齐结果保存逐句开始、结束、置信度和匹配率；高置信度时再开放逐词高亮。
- 无法可靠对齐的句子显示“未听清/疑似漏唱”，不伪造精确时间。

### 2.5 足量生成

- 核心小样仍生成一个版本，用于快速判断方向。
- 完整歌曲默认生成两个独立候选，才能进入 A/B 采用流程。
- 根据批准歌词字数、BPM 和每字可唱时长计算最低完整时长；内容装不下时自动提升到 90、120 或 180 秒，并在提交前显示原因。
- 如果实际有声演唱覆盖率明显低于目标，版本标记为“演唱覆盖不足”。

### 2.6 A/B 试听后采用

- A、B 各有独立的“试听/暂停”、播放进度、当前播放标识和从头播放。
- 打开对比不会自动应用任何版本。
- 用户听过候选后点击“采用 A”或“采用 B”；采用只切换正式当前版本，不删除另一候选。
- 未保存真实音频或歌词质量未通过的候选不能被采用为交付版本，但仍可试听并查看原因。

## 3. 推荐架构

### 3.1 音乐内容总监与歌词逻辑门

生成歌词前增加一个独立的内容规划步骤：

1. 从用户素材提取不可丢失的事实卡片。
2. 建立“开场 → 事实推进 → 冲突/转折 → 核心判断 → 收束”的叙事线。
3. 给每个段落分配事实与情绪任务。
4. 产出歌词后反向检查每句来源、因果连续性和结论完整性。
5. 显示给用户确认，再进入唱法和音乐生成。

歌词逻辑门至少检查：主题是否一致、事实覆盖是否足够、相邻段落是否有因果或转折、结论是否来自素材、专有名词是否保持、是否存在只有押韵没有含义的空句。

采用[专业中文流行歌词模式研究](../../research/2026-08-29-professional-chinese-lyrics-competitive-brief.md)中的市场规则：

- 写作路线不再只叫“诗歌/散文”，而是“把故事唱清楚、像当面说给他听、用一个意象贯穿、把观点唱成力量、先做一句能记住的副歌”。
- 增加“直白、适度抽象、诗性”三级抽象控制；无论哪一级，事实、专有名词、数字、立场和因果默认锁定。
- 诗性路线先建立“核心意象—对应事实—情绪作用”表，一首歌最多使用一到两个中心意象。
- 副歌必须是主歌事实与矛盾推进后的结论，不能在没有铺垫时直接生成口号。

音乐模型启动前显示专业歌词评分卡：核心命题、人物关系、事实覆盖、段落推进、意象一致、副歌因果、可演唱性和陈词滥调风险。任一底线项未通过时返回定向重写，不进入演唱确认。

对体育评论、口播、聊天记录等长文本，默认推荐“叙事念唱/对话唱”并根据内容量给出 120–240 秒时长，而不是强制压缩成普通 60 秒流行歌。

### 3.2 生成前歌词编译器

新增纯函数模块，把已批准歌词编译为 ACE-Step 输入：

1. 去除空行和旧结构标签。
2. 按中文标点和 6–10 字长度拆分，但不改变正文字符和顺序。
3. 根据已批准歌曲结构分配 Verse、Pre-Chorus、Chorus 和 Outro。
4. 输出模型歌词、原歌词字符映射、建议时长、预计演唱覆盖率。

生成请求继续显式传 `lyrics`、`vocal_language=zh` 和 `audio_duration`。不启用任何会重写当前歌词的格式化选项。

### 3.3 本地歌词对齐与咬字审计服务

LocalAudioService 增加：

- `POST /local-audio/align-lyrics`
- 输入：真实人声 WAV、批准歌词、语言。
- 输出：转写文本、逐词时间戳、逐句时间范围、逐句匹配率、重点词匹配率、平均识别置信度、总体忠实度、演唱覆盖率和警告。

第一版使用本机 Apple Silicon 可运行的 MLX Whisper large-v3-turbo 做中文词级转写，再用单调动态规划把转写字符与批准歌词顺序对齐。不能匹配的内容保留为差异，不强行套入批准歌词。

对齐分两层：

- 无提示转写用于忠实度审计，防止模型被批准歌词诱导后“听成”正确答案。
- 带批准歌词上下文的转写用于提高正确版本的时间戳稳定性，但只有与无提示结果一致的区间才能获得高置信度。

### 3.4 三道质量门

候选依次经过：

1. **歌词逻辑门**：生成前确认内容骨架、事实映射和段落推进。
2. **唱词忠实门**：生成后比较实际转写与批准歌词，检查漏唱、改词、乱序和新增歌词。
3. **咬字清晰门**：检查逐句识别置信度、重点词和可懂度，低质量候选不交付。

每个候选具有独立质量状态：

- `processing`：正在分轨和转写。
- `passed`：音频、保存、歌词逻辑、唱词忠实度、咬字、演唱覆盖率和时间轴都通过。
- `warning`：可试听，但存在少量疑似错字或低置信度句子。
- `failed`：明显漏唱、改词、歌词顺序错乱或无法对齐。

建议阈值：

- 总体字符匹配率不低于 0.88。
- 关键副歌不低于 0.92。
- 专有名词、数字和结论重点词匹配率不低于 0.92。
- 逐句平均识别置信度低于基准阈值时进入人工复听，而不是自动通过。
- 批准歌词句子覆盖率不低于 0.90。
- 实际人声有效时间不低于预计演唱时间的 0.80。

阈值写成可测试配置，实机基准后可调整。质量门失败不会删除音频，用户可以试听失败原因或一键重新生成。

## 4. 旧版本清理与重新生成

用户已经要求删除当前作品中所有旧生成结果。清理范围：

- 所有生成版本和音高编辑版本。
- 对应模型原声、柔化混音、完整混音。
- 真实 Stem、歌词时间轴、音高分析和重新混音产物。
- 当前作品的生成任务与交付状态。

保留用户创意、已批准方向、歌词草稿和生成偏好，以便重新生成；如果旧批准歌词本身需要重新拆句，只改变结构和换行，不改变正文。

产品增加“清空本作品生成结果”动作，先列出数量和影响，再进行一次确认。清理必须同时更新前端状态、IndexedDB 资产索引和本地音频服务登记资产。任一步失败时保留记录并显示可重试错误，不能只把卡片从界面隐藏。

本次实施完成并通过自动测试后，再执行一次实际清理和重新生成。为了避免把旧 Bug 生成的歌曲再次混入验收，新生成之前不保留旧音频候选。

## 5. 界面行为

### 5.1 生成结果

每个候选显示：

- 真实时长。
- 已批准歌词行数和实际匹配行数。
- 歌词忠实度、覆盖率和对齐状态。
- 中文咬字清晰度和重点词通过数量。
- “试听”与“进入 A/B”。
- 失败时的“重新生成此候选”。

### 5.2 跟唱歌词

- 播放时以真实逐句时间高亮。
- 点击歌词跳到真实人声开始位置。
- 疑似错唱句显示警告图标和转写差异，不假装已经同步。
- 每句可以切换“批准歌词 / 实际听到”，帮助用户判断到底是歌词写错、模型唱错还是吐字不清。
- 只有 `aligned` 且达到置信度的时间范围可用于逐句音高编辑。

### 5.3 A/B 对比

- 两栏都包含完整播放器。
- 播放 A 时自动暂停 B，反之亦然。
- 采用按钮与试听按钮分开。
- 采用后对话框不强制关闭，用户可以继续核对并撤回到另一版。

## 6. 错误与恢复

- 分轨失败：混音仍可试听，但歌词对齐显示“等待真实人声”。
- 转写失败：不退回伪精确时间轴，提供重试。
- 只有一个候选成功：允许试听成功版本，但不显示为完整 A/B。
- ACE-Step 离线：保留全部输入，恢复后重试；不生成演示音频冒充结果。
- 应用重开：恢复候选、质量状态、对齐结果和 A/B 试听记录。

## 7. 测试与实机验收

### 自动测试

- 歌词拆句不丢字、不换字、不改变顺序。
- 内容骨架能覆盖人物、事实、因果、转折和结论，空泛押韵句会被拦截。
- 原素材专有名词和关键数字在歌词事实映射中可追溯。
- 结构标签不会进入可见歌词。
- 中文重复句、标点、同音错字、漏句和模型新增歌词能被顺序对齐。
- 低匹配率不能通过交付门。
- 重点词不清或平均转写置信度过低不能通过咬字门。
- 新人声歌曲不能用 `estimated` 时间轴通过交付。
- 完整生成提交两个候选；小样仍为一个。
- A/B 试听不会改变正式当前版本，采用才改变。
- 清空作品会删除版本、所有独占资产和任务，不删除创意与歌词草稿。

### 实机验收

1. 清空当前作品旧生成结果。
2. 用当前已批准歌词生成两个完整候选。
3. 先复核内容骨架、事实映射与歌词逻辑，不合格则不启动音乐模型。
4. 对每个候选运行 Demucs 和 MLX Whisper。
5. 人工听查转写、逐句时间、重点词咬字和原歌词一致性。
6. 验证 A、B 可以分别试听，未采用前正式版本不变。
7. 只允许歌词逻辑、忠实度和咬字均通过的候选进入交付确认。
8. 刷新页面后再次播放，歌词仍与声音同步。

## 8. 非目标

- 不承诺 ACE-Step 每次都能逐字正确；产品通过质量门识别失败并重新生成。
- 不使用平均估时伪装真实对齐。
- 本轮不引入需要音符/MIDI与独立声库的专业歌声合成系统。
- 不把旧的错误音频自动修饰成“合格成品”。
