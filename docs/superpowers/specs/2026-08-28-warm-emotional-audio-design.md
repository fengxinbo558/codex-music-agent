# 温暖细腻生成与柔化重制设计

## 背景

当前真实 ACE-Step 生成链路已经能生成、保存、试听、导出和管理多个版本，但部分结果存在三个相关问题：高频与齿音偏尖、演唱和节奏带有明显的机械感、情绪强弱变化不够细腻。

本设计采用“生成阶段引导 + 本机音频柔化”的双层方案。生成引导改善演唱、呼吸、动态和编曲留白；真实音频处理稳定削弱刺耳频段并增加温暖感。两层缺一不可：只改提示无法稳定控制音色，只做后期又无法改变演唱表达。

## 目标

- 新歌默认获得更温暖、柔和且有细微动态的声音。
- 旧的真实音频版本可以非破坏式地生成一份柔化重制版。
- 小白只面对直观的声音质感选择，不需要理解均衡器、压缩器或母带术语。
- 原始模型输出始终保留，可随时与柔化结果试听比较。
- 任一柔化步骤失败时，已经生成的原始音乐仍然可播放、保存和导出。

## 不在本期范围内

- 不训练或微调 ACE-Step 模型。
- 不实现专业多段均衡器、手动画曲线或第三方插件系统。
- 不承诺每一次生成都能达到真人歌手水平；产品应如实表达这是改善而非保证。
- 不对用户导入的参考素材自动处理；只有生成结果和用户主动选择的旧版本进入柔化流程。

## 已选方案

采用双层处理：

1. 在 ACE-Step 请求中加入与声音质感对应的正向音乐描述和负面约束。
2. 对模型返回的 WAV 在本机执行轻量、可重复的柔化母带处理。
3. 保存原始音频和柔化音频之间的来源关系，默认播放柔化版本。

备选方案中，提示词单层方案稳定性不足；后期单层方案无法改善机械演唱和情绪平直，因此均不采用。

## 用户体验

### 新歌

生成设置增加“声音质感”，提供三个选项：

- **温暖细腻**：默认。更柔和的高频、自然呼吸和更明显但克制的情绪推进。
- **自然原声**：处理更轻，尽量保留模型本来的空气感与动态。
- **清晰明亮**：不刻意压暗，仍保留防刺耳和防削波保护。

折叠状态的生成摘要中显示当前质感。用户不展开设置也会自动使用“温暖细腻”。

模型生成完成后，界面依次显示“正在柔化尖锐高频”和“正在保存新版本”。通常处理耗时为几秒到十几秒，但界面不承诺固定时间。

每个生成结果在版本列表中仍只显示为一个作品版本，避免把版本数量无意义地翻倍。该版本默认播放柔化音频，同时保留原始音频作为来源素材。版本详情提供“原声 / 柔化”即时切换，导出当前正在选择的声音。

如果用户选择“清晰明亮”，界面仍使用“原声 / 优化”措辞，避免把明亮版本误称为柔化版。

### 旧版本

拥有真实本机音频、且尚未由柔化动作产生的版本显示“柔化重制”。点击后直接按“温暖细腻”处理，不再弹出专业参数窗口。

处理成功后，新建一个独立版本，例如“版本 07 · 温暖重制”，并自动切换到新版本播放。新版本记录原版本为父版本，原版绝不覆盖。已经柔化过的版本显示“已柔化”，不允许重复叠加处理。

旧版本柔化产生的新版本也可通过现有 A/B 功能与原版本比较。

## 数据模型

新增 `ToneProfile`：`warm | natural | bright`。

`GenerationPreferences` 增加 `toneProfile`，默认值为 `warm`。读取旧的本机设置或旧版本时，如果字段缺失则迁移为 `warm`，避免旧数据导致界面或请求异常。

`ProjectVersion` 增加可选的音频优化信息：

- `parentVersionId`：旧版本重制时指向来源版本。
- `mastering.profile`：实际采用的质感。
- `mastering.sourceAssetId`：保留的模型原始音频素材。
- `mastering.processedAt`：处理时间。

现有 `audioAssetId` 继续指向该版本默认播放和导出的音频：优化成功时指向优化素材，优化失败时指向原始素材。这样旧代码和旧版本保持兼容，也不会为同一主音频维护两套指针。

`MusicAsset` 增加可选的 `visibility` 和 `audioRole`。模型原始音频标记为 `source` 并从普通素材库列表隐藏，但仍可通过版本的“原声”切换读取；优化音频标记为 `mastered` 并正常出现在素材库。用户主动导入和已有素材默认保持可见，兼容旧数据。

版本持久化继续使用现有本机版本存储，音频二进制继续使用 IndexedDB。无需升级或破坏现有数据库结构，因为对象存储允许新增对象字段。

## 组件与职责

### 1. 声音质感定义

一个独立模块集中保存三个质感的用户文案、正向描述、负面描述和母带参数。界面、ACE-Step 提供器和后期服务只读取该定义，避免三处出现不一致的硬编码。

### 2. ACE-Step 生成引导

现有音乐提示组合器追加当前质感的描述。默认“温暖细腻”包含以下意图：亲近且细腻的演唱、自然呼吸和微动态、人性化的节奏轻重、温暖音色、平滑上中频、克制而有层次的情绪推进、编曲保留空间。

请求同时使用 ACE-Step 已支持的 `lm_negative_prompt`，抑制金属感、脆硬高频、尖锐齿音、过度压缩、机器人式咬字、僵硬节奏和完全平直的动态。纯音乐模式移除与演唱相关的描述，只保留动态、音色和编曲要求。

参考风格与翻唱模式仍尊重用户选择的参考音频；质感引导作为质量约束叠加，不改变现有参考强度和任务类型。

### 3. 本机音频优化服务

新增独立的音频优化服务，输入为音频 `Blob` 与 `ToneProfile`，输出为新的 WAV `Blob` 和处理报告。服务不读取 React 状态，也不负责保存数据，因此可以独立测试。

默认“温暖细腻”处理链：

1. 解码真实音频并保留原采样率和声道数。
2. 约 300 Hz 附近极轻微增加厚度。
3. 约 3 kHz 附近轻微削弱容易刺耳的人声存在感区域。
4. 从约 6 kHz 开始柔和地下调高频搁架，抑制齿音和金属感。
5. 使用低压缩比和较慢起音的动态压缩，保留呼吸及强弱而不是把声音压平。
6. 检测输出峰值并留出约 1 dB 余量，防止削波。
7. 编码为可直接播放和导出的 PCM WAV。

具体增益保持在轻量范围，单个频段默认不超过约 3 dB。`natural` 使用更轻的同类处理；`bright` 不削暗整体高频，只控制刺耳区域、动态和峰值。参数由一个纯配置对象提供，以便测试和后续微调。

### 4. 生成协调与保存

生成协调层负责：接收模型结果、保存原始音频、调用优化服务、分析优化后的波形、保存优化素材、建立版本关系、更新当前播放对象。处理多版本时逐个完成，并维持原有批量结果顺序。

保存顺序保证可恢复：先保存原始素材，再尝试优化，再保存优化素材，最后写入可见版本。中途失败时清理未被版本引用的半成品素材。

### 5. 版本操作

版本工作区和生成结果区共享一个“柔化重制”动作。动作只接收来源版本 ID，由协调层读取其真实音频并创建新版本。按钮在处理期间禁用并显示进度，防止重复点击。

原声/优化切换只改变当前播放素材，不改变歌曲结构、歌词、BPM、调性或轨道信息。切换状态跟随当前版本，不影响其他版本。

界面使用独立的 `source | optimized` 试听状态解析实际素材：`source` 读取 `mastering.sourceAssetId`，`optimized` 读取现有 `audioAssetId`。进入一个已优化版本时默认选择 `optimized`；刷新后也恢复为默认优化音频。导出读取当前试听状态对应的素材，而不是始终固定读取版本主素材。

## 数据流

### 新歌生成

用户想法与质感设置 → Agent 制作方案 → ACE-Step 正向与负面引导 → 模型原始 WAV → 保存隐藏来源素材 → 本机音频优化 → 保存可见优化素材 → 建立单一作品版本 → 自动播放优化结果。

### 旧版本柔化

当前版本 → 读取本机真实音频 → “温暖细腻”优化 → 保存新素材 → 新建带父版本关系的“温暖重制”版本 → 自动切换播放。

## 错误与恢复

- **模型失败**：沿用现有错误提示和重试逻辑，不创建音频或版本。
- **新歌生成成功但优化失败**：保存并显示原始模型结果，版本标记为“原声可用，柔化未完成”，提供“重试柔化”；不能把整次创作误报为失败。
- **旧版本优化失败**：保留当前版本，不创建空的新版本，用户可直接重试。
- **本机不支持音频处理或解码失败**：明确说明“歌曲已保留，但当前环境未完成柔化”，禁止假装处理成功。
- **保存失败**：清理没有被版本引用的新增素材；已经存在的来源版本不受影响。
- **页面刷新**：从持久化的版本关系恢复默认优化音频及原声切换能力。

## 测试与验收

### 自动测试

- 三个质感的默认值、标签、摘要和旧数据迁移正确。
- ACE-Step 正向提示和 `lm_negative_prompt` 包含对应约束；纯音乐不包含演唱描述。
- 参考风格、翻唱和自由生成都保留原任务字段并正确附加质感。
- 音频优化配置符合约束：频段增益不过量、温暖档高频下调强于自然档、明亮档不整体压暗。
- WAV 编码具有合法文件头、正确声道数、采样率、时长与有限样本值。
- 输出峰值不削波并留有目标余量。
- 优化失败时保留原始版本；保存中断时不留下无引用半成品。
- 已柔化版本不能重复处理，旧版本和缺少真实音频的版本得到正确按钮状态。

### 浏览器验收

1. 使用默认设置真实生成一首歌，确认进度经过生成、柔化和保存三个阶段。
2. 播放时间真实推进，刷新页面后仍能播放。
3. 切换“原声 / 柔化”，确认两者来源不同且可重复 A/B 试听。
4. 柔化一个现有版本，确认产生独立新版本且原版仍存在。
5. 分别生成温暖、自然、明亮三种质感，确认设置和版本元数据正确。
6. 导出当前选择的声音并重新导入，确认文件可解码、可播放、时长正确。
7. 模拟音频处理失败，确认生成的原始歌曲仍然可用且提示真实。

### 主观声音验收

使用同一模型结果进行原声与柔化盲听。默认温暖档应满足：齿音和高频不再明显扎耳；人声主体不发闷；鼓和瞬态仍有力度；强弱呼吸没有被压平。生成侧以多次结果抽查自然咬字、情绪推进和编曲留白，不把单次随机结果当作成功证明。

## 完成标准

- 默认新歌实际经过温暖细腻生成引导与音频优化。
- 旧真实版本可以一键生成非破坏式柔化版本。
- 原声始终保留，优化失败不会丢歌。
- 用户无需专业音频知识即可完成质感选择、试听对比和导出。
- 自动测试、生产构建和真实浏览器验收全部通过。
