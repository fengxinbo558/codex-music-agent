# 真实音乐工作流、中文清晰演唱与跟唱歌词设计

日期：2026-08-28
范围：Codex Music Agent Studio 下一阶段
状态：待用户书面确认后实施

## 1. 背景与目标

当前产品已经打通真实 ACE-Step 生成、参考音频、浏览器本地保存、试听、版本切换和 WAV 导出，但界面存在能力表达大于真实能力的问题：

- 入口中的“理解创意、规划结构、调用模型、保存版本”是固定说明，没有展示每一步的真实输入、产物和完成依据。
- 多轨混音、添加音轨、静音/独奏只改变界面状态，无法改变当前单一混合 WAV。
- 局部重绘、续写、重新编曲和“只改副歌”尚未完整映射到 ACE-Step 对应任务。
- 一部分百分比由定时器推进，不代表模型返回的真实进度。
- 当前温暖母带会降低尖锐感，但也可能削弱中文辅音和咬字存在感。
- 播放器没有跟随歌曲显示歌词。

本阶段目标：

1. 只把已被工具结果证明的步骤标成完成。
2. 让用户看懂不同音乐专业角色分别做了什么、交给了谁。
3. 默认提高中文歌词可懂度，同时继续控制尖锐和齿音。
4. 播放时提供可跟唱、可跳转的歌词界面。
5. 未接通的底层能力必须锁定或明确标注，不再伪装成可用功能。

### 2.1 借鉴

- 专业 Agent 具有明确身份、输入、输出、完成条件和下游接收者。
- 每一阶段的产物进入共享画布，而不是只存在聊天文字中。
- 用户在高成本或高影响步骤前确认，确认后才进入下一阶段。
- 先生成一个小样，再决定是否批量生成，降低错误放大。
- 上游产物成为下游的结构化输入，而不是重复拼接自然语言。

### 2.2 不照搬

- 不复制 OiiOii 的视觉布局、角色名称、文案或黑色节点画布。
- 不采用大量连续确认；小白默认自动推进，只保留两个关键确认点。
- 不让聊天、画布、任务、素材库分别维护状态。
- 不以 Agent 的“我完成了”作为完成事实。
- 不在底层工具缺失时展示可执行按钮。

## 3. 产品原则

### 3.1 Agent 是专业职责，不是装饰性头像

每个 Agent 必须满足：

- 有结构化输入。
- 产生可查看的结构化产物。
- 有可验证完成条件。
- 只在完成条件通过后交接。
- 失败时保留输入和旧版本，并给出可执行恢复入口。

多个专业角色不等于每一步都单独调用收费大模型。初期可由一个 Codex 规划请求或本地规则生成多个角色产物；音乐模型仍是工具，不伪装成 Agent。

### 3.2 一个状态事实源

创作台、Agent 面板、任务区、版本区和素材库都读取同一个 `MusicWorkflowState`。音频文件成功写入本机素材库之前，不显示“作品已完成”。

### 3.3 小白默认自动，高级用户可以展开

用户仍可只写一句创意并生成。专业 Agent 链默认自动运行，用户可展开查看每一步，不需要逐项填写专业参数。

## 4. 音乐专业 Agent 架构

### 4.1 主控：音乐制片人

职责：读取用户创意、当前工程、歌词和生成设置，组织工作流，检查前置条件，决定是否需要用户确认。

输入：`CreativeRequest`、当前版本、参考音频、生成设置。
输出：工作流实例、步骤状态、确认请求。
完成条件：下游所需字段齐全，或明确指出缺项并阻断。
边界：不直接声称音乐已经生成，不制造音频资产。

### 4.2 音乐总监

职责：把自然语言创意整理成清楚的创作方向。

输入：用户创意、参考音频摘要、历史偏好。
输出：`CreativeBrief`，包含主题、情绪推进、曲风、听众场景、时长和必须保留内容。
完成条件：必填字段通过校验，并显示给用户。
下游：作词人、编曲师、演唱指导。

### 4.3 作词人

职责：生成或整理可演唱歌词。

输入：`CreativeBrief`、用户当前歌词、歌词模式、目标时长。
输出：`LyricsDraft`，包含段落标签、逐行歌词、字数预算和过长警告。
完成条件：每个演唱段落有内容；行长适合中文咬字；总字数不超过时长预算，或明确要求分段续写。
边界：选择“使用当前歌词”时不改写用户原文，只允许增加不参与演唱的结构信息。

### 4.4 编曲师

职责：确定结构、速度、调性、配器和动态推进。

输入：`CreativeBrief`、`LyricsDraft`、参考风格。
输出：`ArrangementPlan`。
完成条件：结构时长合计合理，配器与演唱空间不冲突。
边界：当前只产生生成条件；没有真实分轨时不展示可混音的独立音轨。

### 4.5 演唱指导

职责：把人声类型、怒声/嘶吼程度、中文咬字、呼吸、混响和前后位置编译成真实模型参数。

输入：歌词、演唱方式、演唱状态、清晰度设置、音色方向。
输出：`VocalPlan`，包含正向约束、负向约束、语言和清晰度策略。
完成条件：中文歌曲固定写入 `vocal_language=zh`；清晰模式必须实际改变 ACE-Step 请求。
下游：音乐模型工具。

### 4.6 混音与母带师

职责：保存模型原声，并生成一个不覆盖原声的优化版本。

输入：真实生成 WAV、质感设置、清晰度设置。
输出：`SourceAudioAsset` 和 `MasteredAudioAsset`。
完成条件：两个资产均可读取；优化失败时仍保留原声。
边界：未完成分轨前只做整首母带，不展示假分轨混音能力。

### 4.7 质检师

职责：判断结果是否具备交付条件。

输入：音频资产、目标时长、歌词、版本记录、歌词时间信息。
输出：`QualityReport` 和 `ReadyGate`。
初期硬检查：文件存在、可解码、时长合理、版本引用正确、歌词已关联、素材库写入成功。
边界：没有可靠听写或对齐模型时，不声称“歌词咬字评分通过”。

## 5. 工作流与两个确认门

### 5.1 自动主链

用户创意
→ 音乐总监生成方向卡
→ 作词人生成/校验歌词卡
→ 编曲师生成结构卡
→ 演唱指导生成演唱卡
→ 前置检查
→ ACE-Step 接收任务
→ 音频写入素材库
→ 母带优化
→ 歌词时间生成
→ 质检完成门
→ 新版本可播放

### 5.2 确认门一：生成前

默认展示一张合并的“制作方案”卡：主题、曲风、结构、歌词摘要、演唱方式、预计时长和版本数量。

- 普通一句话创作：默认 5 秒后自动继续，也可立即生成或修改。
- 使用长篇原文、翻唱源音频、极限嘶吼等高影响模式：必须显式确认。

### 5.3 确认门二：首版后

第一首真实版本完成后显示：

- 满意，设为当前版本并继续。
- 再生成一个版本。
- 修改歌词。
- 调整演唱清晰度。

只有用户选择生成多个版本时才继续批量，不默认浪费时间。

## 6. 真实进度与完成定义

取消固定介绍步骤和纯定时百分比，改为事件驱动的步骤卡：

1. `BRIEF_READY`：创作方向已经写入项目状态。
2. `LYRICS_READY`：歌词或纯音乐状态已经确认。
3. `MODEL_TASK_ACCEPTED`：ACE-Step 返回真实任务 ID。
4. `MODEL_RUNNING`：显示服务返回的真实阶段；未知阶段显示“音乐模型正在生成”，不编造细节。
5. `AUDIO_RECEIVED`：真实 WAV 已经读取。
6. `AUDIO_STORED`：真实 Blob 和资产记录已经写入 IndexedDB。
7. `MASTER_READY`：母带成功，或明确标记母带失败并保留原声。
8. `LYRICS_TIMED`：歌词时间信息已建立。
9. `READY`：完成门通过，可以试听和导出。

完成条件：

- 当前版本引用一个存在的音频资产。
- 音频 Blob 可以从本机素材库重新读取。
- 音频元数据可读且时长大于零。
- 有人声时，版本关联对应歌词和歌词时间来源。
- UI、任务区、素材库读取同一个 `READY` 状态。

ACE-Step 离线时，主生成按钮显示“启动真实音乐模型”，不再用 16 秒合成试听冒充一次正常生成。开发者链路试听移到模型中心并明确标记。

## 7. 中文歌词清晰度

### 7.1 新设置

增加“歌词清晰优先”开关，人声歌曲默认开启，纯音乐自动隐藏。该开关必须同时影响歌词准备、ACE-Step 请求和母带参数。

### 7.2 歌词准备

- AI 歌词使用 `[Verse]`、`[Pre-Chorus]`、`[Chorus]`、`[Bridge]` 等结构标签。
- 中文演唱行优先控制在 6–14 个汉字；过长句按语义和标点拆行。
- 不连续堆叠专有名词、数字和长定语。
- 使用当前歌词时保留原字，只给出“这一行可能听不清”的提示，不静默改词。

### 7.3 ACE-Step 参数

清晰模式至少写入：

- `vocal_language: "zh"`。
- Turbo 模型使用官方文档建议的 `shift: 3.0`，强化语义骨架。
- 使用受控的 `lm_cfg_scale` 提高生成条件遵循度；首轮从 2.4 开始，经固定 seed A/B 后确认。
- 正向描述包含：人声靠前、近讲麦克风、清楚中文声母韵母、克制混响、伴奏为人声留出中频空间。
- 负向描述包含：含混咬字、吞字、过量混响/延迟、人声被伴奏掩盖、刺耳齿音、数字削波。

本阶段不承诺逐字准确。模型生成清晰度只能通过参数和筛选改善，不能由界面保证。

### 7.4 清晰母带

- 保留温暖模式对 6–8kHz 刺耳高频的控制。
- 减少对 2–4kHz 咬字存在感区域的整体衰减。
- 使用轻度压缩保持人声稳定，不以大幅高频提升制造“假清晰”。
- 模型原声和清晰母带都保留，可即时对比。

## 8. 跟唱歌词界面

### 8.1 用户界面

在时间线和底部编辑区之间增加“歌词跟唱”面板：

- 当前句居中放大并使用金铜色高亮。
- 上一句和下一句降低亮度。
- 播放时自动滚动。
- 点击任意一句跳到对应时间。
- 可折叠，不遮挡编辑歌词。
- 纯音乐显示“当前版本为纯音乐”。

### 8.2 数据模型

```ts
type LyricCue = {
  id: string;
  text: string;
  start: number;
  end: number;
  source: "estimated" | "aligned";
};
```

第一版使用“结构 + 行长 + 音频总时长”的确定性估时，并在面板上显示“智能估时”。它不是逐字 LRC，不伪装成真实对齐。

未来接入 ACE-Step LRC 或本地强制对齐服务时，将 `source` 改为 `aligned`，界面和版本结构无需重做。

## 9. 功能真实性处理

### 9.1 保留为可用

- 整首真实生成。
- 女声、男声、纯音乐。
- 当前歌词和 AI 写词。
- 怒声摇滚、极限嘶吼。
- 参考风格和翻唱/重编。
- 版本生成、选择、A/B 对比。
- 素材库保存、播放和 WAV 导出。
- 模型原声与母带版本。

### 9.2 暂时锁定并说明依赖

- 局部重绘与“只改副歌”：锁定，直到真实传入源音频、重绘起止时间和 `task_type=repaint`。
- 续写：锁定，直到真实传入源音频上下文并完成拼接验证。
- 重新编曲：只有使用参考源音频并走 cover/remix 时可用。
- 多轨混音、静音、独奏、添加音轨：锁定，提示“需要真实分轨结果”。

锁定能力保留在“即将接通”说明中，不占据小白主路径。

## 10. 状态与数据

核心对象：

- `MusicWorkflowState`：当前步骤、真实事件、错误、确认门和完成状态。
- `CreativeBrief`：音乐总监产物。
- `LyricsDraft`：作词人产物和时长预算。
- `ArrangementPlan`：编曲师产物。
- `VocalPlan`：演唱指导产物和清晰度约束。
- `GenerationRun`：Provider、任务 ID、模型参数、seed、阶段和错误。
- `AudioAsset`：素材库中的不可变音频引用。
- `ProjectVersion`：引用上述产物和资产，不保存会失效的临时 Blob URL。
- `LyricCue[]`：歌词显示时间及来源。
- `QualityReport`：硬检查结果和未验证项目。

依赖关系：

`CreativeBrief → LyricsDraft + ArrangementPlan + VocalPlan → GenerationRun → SourceAudioAsset → MasteredAudioAsset → LyricCue/QualityReport → ProjectVersion`

上游内容修改时新建版本，不覆盖已经生成的音频。当前阶段不自动重跑下游；UI 明确提示哪些产物已经过期。

## 11. 错误与恢复

- 模型离线：保留创意和设置，显示启动模型入口，不创建假版本。
- 模型任务失败：保留任务 ID、错误和输入，可重试；不覆盖旧版本。
- 音频收到但保存失败：版本不进入 `READY`，允许重新保存或下载临时结果。
- 母带失败：原声仍可播放和导出，优化版本标记失败。
- 歌词估时失败：歌曲仍可播放，跟唱面板显示未同步，不影响音频资产。
- 页面刷新：从 IndexedDB 和本地状态恢复同一个工作流投影。

## 12. 测试与验收

### 12.1 单元测试

- 清晰度设置真实映射到 ACE-Step 请求字段。
- 清晰模式包含中文咬字正向/负向约束和 `shift=3.0`。
- 当前歌词不被静默改字。
- 歌词行估时覆盖整段音频，时间单调且不越界。
- 当前播放时间能稳定选择正确歌词行。
- 完成门在音频未保存时拒绝 `READY`。
- 锁定功能不会触发生成任务。

### 12.2 集成测试

- 真实生成：任务接受 → WAV 获取 → 素材保存 → 版本建立 → 跟唱歌词出现。
- 离线：不创建假歌曲版本。
- 保存失败：任务区、素材库和播放器状态一致。
- 刷新后：音频、版本、歌词和步骤状态能够恢复。

### 12.3 听感验证

使用同一歌词、同一 seed、同一时长生成 A/B：

- A：现有参数。
- B：歌词清晰优先。

人工听测至少检查：歌词可辨识度、齿音尖锐度、人声是否被伴奏遮挡、情绪是否变平。只有 B 在清晰度提升且不重新引入尖锐感时，才设为默认。

## 13. 实施分期

### 第一阶段：真实性与清晰度

- 真实工作流状态和步骤卡。
- 锁定无底层能力的控件。
- 歌词清晰优先参数和母带。
- 估时跟唱歌词。
- 完成门与恢复测试。

### 第二阶段：真实编辑

- 接通 ACE-Step repaint 和真实“只改副歌”。
- 接通续写、拼接和版本依赖。
- 接入真实 LRC/强制对齐。

### 第三阶段：真实分轨

- 接入分轨模型。
- 让混音、静音、独奏和添加音轨真正控制音频。
- 增加分轨级版本、导出和质检。

## 14. 本阶段不做

- 不训练或微调 ACE-Step。
- 不声称达到 Suno/Udio 的歌词准确度。
- 不把六个角色拆成六次付费模型调用。
- 不实现云账号、协作、计费或发布。
- 不复制 OiiOii 的视觉和文案。
